# ADR 0003: Encryption is on by default and pre-configured

- Status: Accepted
- Date: 2026-11-06
- Owner requirement: "Por defecto viene todo encriptado como proton ya pre-configurado." (encryption like Proton, on by default, zero setup)

## Decision

Pigeon ships encrypted out of the box; **there is no configuration needed and no standard opt-out**:

1. **At rest (always)** — every stored message body/attachment is ciphertext (XChaCha20-Poly1305). The master key is **auto-generated by the installer** (`openssl rand`-strength 32 bytes) into a root-owned key file; the server refuses to boot storage without it. Backups of the DB without the key file are useless by design.
2. **In transit (default)** — API behind TLS (installer provisions via Let's Encrypt/Caddy), inbound SMTP with STARTTLS advertised, **outbound SMTP requires STARTTLS** (opportunistic with pinning mode `strict` available); downgrade to plaintext outbound requires an explicit per-domain override.
3. **End-to-end (automatic when possible)** — Pigeon↔Pigeon traffic is E2E encrypted automatically (instance keys + auto-discovery); outbound to any domain that publishes an OpenPGP key via WKD is sealed automatically. No checkbox anywhere.

The full model, its Proton-modeled guarantees, and its **honest limits** (subject lines, inbound SMTP plaintext window) are specified in [e2ee-model.md](../e2ee-model.md). Disabling encryption at rest or the master key requirement is not a supported configuration; anyone needing plaintext storage should run a different product.
